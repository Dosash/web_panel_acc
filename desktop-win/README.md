# TG Panel для Windows — Tauri 2 + WebView2

Программа для Windows 10/11 x64: то же, что [desktop/](../desktop/README.md) (окно к панели — своей или на вашем
сервере), но вместо PyQt5 + Qt WebEngine — оболочка на Rust ([Tauri 2](https://tauri.app)) и встроенный в Windows
движок Microsoft Edge WebView2. Linux и macOS по-прежнему собираются из `desktop/`.

Зачем: Qt 5.15.2 под Windows привязан к старому Chromium — интерфейс тормозил, а установщик весил 246 МБ
(из них ~192 МБ — PyQt5, одна `Qt5WebEngineCore.dll` — 97 МБ). WebView2 уже есть в системе и обновляется вместе
с Edge, оболочка весит несколько мегабайт, а Python нужен только серверной части и только в локальном режиме.

## Как устроено

```
TG Panel\
├─ TG Panel.exe                 оболочка (Rust, Tauri 2): окна WebView2, трей, уведомления, загрузки, обновления
└─ server\tg-panel-server.exe   серверная часть (PyInstaller): app/ на 127.0.0.1 — только в локальном режиме;
                                этот же exe запускает встроенных ботов (--bot posts|ads)
```

**Режим сервера** («На моём сервере»): окно открывает адрес панели, например `http://192.168.3.18/accounts/`.
Python не запускается вовсе. Сервер недоступен — свой экран «Сервер панели недоступен» и проверка каждые 10 секунд.

**Локальный режим** («На этом компьютере»): оболочка запускает `server\tg-panel-server.exe --data <папка> --port <порт>`
без окна. Когда сервер готов, он пишет в stdout строку JSON с портом и cookie входа; оболочка кладёт cookie
(HttpOnly, path=/, 30 дней) в профиль WebView2 через CookieManager и открывает `http://127.0.0.1:<порт>/`.
Пароль панели случайный на каждый запуск — другие программы на компьютере в панель не попадут. Выход — «quit»
в stdin (или закрытый stdin, если оболочка упала): lifespan панели штатно отключает аккаунты и ботов; принудительно
процесс завершается только через 15 с. Журнал сервера (stderr) оболочка пишет в общий `tg-panel.log`.

| Файл | Что делает |
|---|---|
| `shell/src/main.rs` | точка входа: обычный запуск, `--apply-update` (помощник обновления), `--check` |
| `shell/src/app.rs` | окна, режимы, навигация (своя панель — в окне, остальное — в браузере), трей, выход, подключение |
| `shell/src/webview.rs` | WebView2 напрямую: клавиши, контекстное меню, разрешения, «Сохранить как», cookie, масштаб, падение страницы |
| `shell/src/page.js` | скрипт в страницу: `TG_DESKTOP`, `TG_DESKTOP_APP`, `visibilityState`, уведомления, плашка обновления |
| `shell/src/server.rs` | процесс серверной части, её JSON-сообщения и журнал |
| `shell/src/updater.rs`, `helper.rs` | обновление: проверка, докачка, SHA-256, установка, откат |
| `shell/src/settings.rs` | `desktop.ini` в формате QSettings — тот же файл, что у прежней программы |
| `shell/src/notify.rs`, `tray.rs`, `autostart.rs`, `placement.rs` | уведомления Windows, трей, автозапуск, положение окна |
| `shell/ui/status.html`, `connect.html` | экраны «Запуск…»/ошибка и выбор подключения (встраиваются в exe) |
| `server/main.py`, `server/tg-panel-server.spec` | серверная часть и её сборка (из PyQt5 — только QtCore для opentele) |
| `installer.iss` | установщик Inno Setup |
| `build.ps1` | сборка всего одной командой |

## Что умеет окно

Всё, что прежняя программа ([desktop/shell.py](../desktop/shell.py)):

- скрипт в главный фрейм каждой страницы: `window.TG_DESKTOP`, `window.TG_DESKTOP_APP = {version, mode, update}`,
  `document.visibilityState` — `"hidden"`, когда окно не в фокусе или в трее; в локальном режиме скрыт `#logout`;
- `<панель>/tg-desktop/update` («Обновить программу» в панели) не открывается, а запускает проверку обновлений;
- адреса своей панели — в окне; data/about/blob и переходы во фреймах (мини-приложения) не трогаются;
  остальное http/https/tg/mailto/tel — в системном браузере или приложении;
- «новое окно» на адрес панели — отдельное окно программы: фото и видео на чёрном фоне (Esc закрывает),
  панель встроенного бота `<панель>/bots/<имя>/` — одно окно на бота, повторно поднимается открытое;
- `new Notification(...)` — системное уведомление Windows от имени TG Panel (AppUserModelID `TGPanel.Desktop`),
  щелчок открывает окно; камера, микрофон и геолокация для мини-приложений — после вопроса;
- загрузки — окно «Сохранить как» (папка запоминается), по окончании — «Файл сохранён», при ошибке — сообщение;
- трей: щелчок — показать/скрыть; меню «Открыть», «Подключение: …», «Папка с данными», «Проверить обновления»,
  «Обновлять автоматически», «Запускать при входе в систему», «Выход». Закрытие окна — в трей;
- одна копия на папку данных; автозапуск — `HKCU\…\Run`, значение «TG Panel», с `--hidden`;
- размер, положение и масштаб запоминаются (Ctrl+колесо, Ctrl+= / Ctrl+− / Ctrl+0), минимум 380×480;
- F5 и Ctrl+R — обновить, F11 — во весь экран (и полноэкранное видео), Ctrl+Shift+I — инструменты разработчика,
  Ctrl+Q — выход; контекстное меню без «Назад/Вперёд/Сохранить страницу»; упавшая страница перезагружается.

## Данные и настройки

Та же папка, что у прежней программы: `%APPDATA%\TG Panel`, у переносной версии — `data` рядом с `TG Panel.exe`
(если рядом лежит `portable.txt`), `TG_PANEL_DATA` — своя папка. Из `desktop.ini` (QSettings) берутся `mode`,
`server_url`, `port`, `zoom`, `auto_update`, `download_dir` — после обновления с PyQt-версии режим не спрашивается
заново (положение окна из Qt не переносится). Профиль WebView2 — `<данные>\webview2` (прежний `webengine` не
трогается), журнал — `<данные>\logs\tg-panel.log` (2 МБ × 4 файла): оболочка, серверная часть, ошибки JS страницы,
помощник обновления. `TG_PANEL_SERVER=http://…/accounts/` — при первом запуске сразу режим сервера, без вопроса.

## Обновление

Совместимо с прежней программой: те же файлы релиза `TG-Panel-<версия>-windows-x64-setup.exe` и `-portable.zip`,
установщик с тем же AppId и папкой. Программа на PyQt5 скачивает новый setup.exe и запускает его с `/SILENT` —
он ставит новую программу поверх и удаляет `_internal`; данные в `%APPDATA%` не трогаются.

Своё обновление — почти незаметное (без tauri-plugin-updater: релизы должны оставаться совместимыми):

1. **Проверка и скачивание — в фоне**: через 30 с после запуска и раз в 6 часов. Докачка с места обрыва (Range)
   и повторы через 5, 15, 30, 60, 120 с; если не вышло — новая попытка через 30 минут.
2. **Целостность**: файл сверяется с `TG-Panel-<версия>-SHA256SUMS.txt` из того же релиза (его добавляет CI).
   Нет суммы или не совпала — файл удаляется, обновление не ставится.
3. **Установка в удобный момент**, без окна Inno Setup (`/VERYSILENT`): окно свёрнуто в трей и программа простояла
   минуту; при выходе; при следующем запуске; или по кнопке «Перезапустить» на плашке «Обновление готово» в окне
   (вместо модального окна). Перезапуск возвращает окно в то же состояние — открыто или в трее.
4. **Локальный режим**: перед установкой сервер останавливается штатно (аккаунты отключаются), после запуска
   подключаются сами. Простой пишется в журнал: «Обновление … простой N с».
5. **Откат**: ставит помощник — копия программы в `<данные>\update\helper`. Перед установкой он сохраняет папку
   программы, после — запускает новую версию и ждёт отметку «поднялась» (окно и сервер). Новая версия упала, вышла
   или не запустила сервер — прежние файлы возвращаются, прежняя версия запускается, причина — в журнал,
   версия — в `<данные>\update\state.json` → `bad`: её программа больше не ставит. Установка «при выходе» проверяется
   без окна: `TG Panel.exe --check` и `tg-panel-server.exe --self-test`.
6. **После обновления** — один раз плашка (или уведомление, если окно в трее) «Обновлено до X.Y.Z» с первыми
   пунктами раздела `CHANGELOG.md`.
7. В трее — «Проверить обновления» и «Обновлять автоматически». Без автообновления программа только сообщает
   о новой версии (пункт меню становится «Обновить до X»).

**Установка «для всех» без окна UAC.** Установщик по умолчанию ставит программу для текущего пользователя
(`%LOCALAPPDATA%\Programs\TG Panel`) — туда обновление пишет без прав администратора. Если программа стоит
«для всех» (`C:\Program Files\TG Panel`), каждое обновление требовало бы подтверждения. Поэтому, когда обновление
скачано, программа один раз предлагает перейти на установку для текущего пользователя: новая версия ставится
с `/CURRENTUSER`, прежняя копия удаляется её деинсталлятором (единственное окно UAC), автозапуск переносится,
аккаунты и настройки остаются — они в `%APPDATA%`. Откажетесь — обновление ставится при выходе или по кнопке,
с подтверждением администратора, как раньше; в трее, без вашего участия, — нет.

Проверить обновление на своём сервере, не публикуя релиз: `TG_PANEL_UPDATE_URL=<адрес JSON как у GitHub API>`.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File desktop-win\build.ps1
```

Нужны: Rust `stable-x86_64-pc-windows-msvc` и Visual Studio 2022 Build Tools («Разработка классических
приложений на C++»), Tauri CLI 2 (`cargo install tauri-cli --version "^2" --locked`), Python 3.12, Inno Setup 6.
Скрипт создаёт `desktop-win\.venv`, рисует значки из `desktop\icon.svg`, собирает серверную часть (и проверяет её
`--self-test`: импорт панели и запись/чтение tdata через opentele), оболочку (`cargo tauri build --no-bundle`),
переносной zip, установщик (с загрузчиком WebView2 Runtime — ставится, только если его нет) и контрольные суммы.
Версия — `VERSION` из `app/config.py`. В GitHub Actions то же самое делает Windows-задача `.github/workflows/desktop.yml`.

Разработка: `cd desktop-win\shell; cargo tauri dev` (или `cargo run`) — без собранной серверной части оболочка
в локальном режиме запускает `desktop-win\server\main.py` через `desktop-win\.venv`. Окно со своей папкой данных:
`$env:TG_PANEL_DATA = "$env:TEMP\tg-panel-test"`.
