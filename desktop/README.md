# TG Panel для компьютера — Windows, Linux, macOS

Та же панель, но отдельной программой — сама по себе или как окно к вашему серверу с панелью. Внутри — тот же
сервер панели из `app/` и тот же интерфейс из `static/`, поэтому всё, что умеет веб-панель, умеет и программа:
импорт из tdata, общий список чатов, папки, каналы и группы, мини-приложения ботов, профиль, сеансы и т.д.
Новые функции панели попадают в программу при следующей сборке — ничего дублировать не нужно.

| Система | Файл | Как установить |
|---|---|---|
| Windows 10/11 x64 | `TG-Panel-<версия>-windows-x64-setup.exe` | запустить установщик (права администратора не нужны) |
| | `TG-Panel-<версия>-windows-x64-portable.zip` | распаковать и запустить `TG Panel.exe`; данные — в папке `data` рядом |
| Linux x86_64 | `TG-Panel-<версия>-linux-x86_64.AppImage` | `chmod +x` и запустить |
| | `TG-Panel-<версия>-linux-x86_64.tar.gz` | распаковать, `./tg-panel/install.sh` — ярлык в меню и команда `tg-panel` |
| macOS 11+ (Apple Silicon) | `TG-Panel-<версия>-macos-arm64.dmg` | перетащить в «Программы» |
| macOS 11+ (Intel) | `TG-Panel-<версия>-macos-x86_64.dmg` | то же |

Готовые файлы — на странице [Releases](https://github.com/Dosash/web_panel_acc/releases) (выпускаются
автоматически при новой версии в main, см. ниже) или в артефактах запуска
[Actions → «Десктоп-приложение»](https://github.com/Dosash/web_panel_acc/actions/workflows/desktop.yml).

## Что добавляет программа к веб-панели

- **Своё окно** со значком; размер, положение и масштаб (Ctrl + колесо, Ctrl+= / Ctrl+− / Ctrl+0) запоминаются.
- **Трей**: закрытие окна сворачивает программу в трей — аккаунты остаются на связи и присылают
  уведомления. Меню значка: открыть, папка с данными, «Запускать при входе в систему», выход.
  Если трея нет (некоторые окружения Linux), закрытие окна завершает программу.
- **Системные уведомления** о новых сообщениях — когда окно свёрнуто или не в фокусе.
- **Вход без пароля**: сервер слушает только `127.0.0.1` на случайном пароле, вход выполняет сама программа.
- **Файлы** из чатов сохраняются через обычное окно «Сохранить как»; фото и видео «в новой вкладке»
  открываются в отдельном окне программы, внешние ссылки — в системном браузере, `tg://` — в Telegram.
- **Одна копия**: повторный запуск показывает уже открытое окно (две копии подключили бы одни и те же
  сессии дважды).
- Горячие клавиши: F5 / Ctrl+R — обновить, F11 — во весь экран, Ctrl+Q — выйти,
  Ctrl+Shift+I — инструменты разработчика.

## Всё едино: сервер, программа, обновления

**Два режима.** При первом запуске программа спрашивает, где работают аккаунты (сменить — трей → «Подключение…»):

| Режим | Что происходит | Когда выбирать |
|---|---|---|
| **На моём сервере** | программа открывает вашу веб-панель, например `http://192.168.1.10/accounts/` | панель уже стоит на сервере: аккаунты, папки и правки панели — общие для браузера, телефона и всех компьютеров |
| **На этом компьютере** | свой сервер панели внутри программы, аккаунты подключаются отсюда | сервера нет; сообщения приходят, пока программа запущена |

В режиме сервера интерфейс приходит с сервера: обновили панель на сервере — на всех устройствах сразу новая
версия, программу трогать не нужно. Если на сервере задан `WEB_PASSWORD`, программа один раз спросит пароль
(вход живёт 30 дней). Сервер недоступен — программа показывает это и переподключается каждые 10 секунд.
Для массовой установки адрес можно задать заранее: переменная `TG_PANEL_SERVER=http://…/accounts/` —
тогда при первом запуске вопроса не будет.

**Обновление самой программы.** Раз в 6 часов (и через 30 секунд после запуска) программа смотрит последний
релиз на GitHub. Если он новее — скачивает файл под свою систему и ставит его после перезапуска:

| Как установлена | Чем обновляется |
|---|---|
| Windows, установщик | новый `setup.exe` в тихом режиме, в ту же папку |
| Windows, portable | файлы из нового zip поверх папки программы (`data` не трогается) |
| Linux, AppImage | новый `.AppImage` на месте старого (папка с ним должна быть доступна на запись) |
| Linux, tar.gz / `install.sh` | новая папка на месте старой |
| macOS | `TG Panel.app` из нового `.dmg` на место старой |

Если окно свёрнуто в трей, обновление ставится сразу и программа возвращается в трей; если открыто — спрашивает
«Перезапустить сейчас» или «При выходе». В трее: «Проверить обновления», «Обновлять автоматически».
Когда поставить нельзя (запуск из исходников, нет прав на папку) — предлагает открыть страницу загрузки.

**Как выпустить новую версию для всех устройств:**

1. Поменяйте панель (`app/`, `static/`) и/или программу (`desktop/`).
2. Повысьте `VERSION` в `app/config.py` и опишите изменения в `CHANGELOG.md` под заголовком `## <версия> — <дата>`.
3. Влейте в `main`. GitHub Actions соберёт программу под Linux, Windows и macOS и опубликует релиз
   `v<версия>` с описанием из `CHANGELOG.md`. Установленные программы обновятся сами в течение 6 часов.
4. Серверную панель обновите как обычно (`git pull && docker compose up -d --build`) — устройства в режиме
   сервера получат новую версию сразу.

## Где хранятся данные

| Система | Папка |
|---|---|
| Windows | `%APPDATA%\TG Panel` |
| macOS | `~/Library/Application Support/TG Panel` |
| Linux | `~/.local/share/tg-panel` |
| Переносная (zip) | `data` рядом с `TG Panel.exe` |

Там же, что и у серверной панели: `panel.db` (сессии зашифрованы), **`secret.key`** (без него сессии
не расшифровать), `cache/`, а ещё `webengine/` (настройки интерфейса), `desktop.ini` (окно, порт)
и `logs/tg-panel.log` — журнал, если что-то не работает. Другую папку можно задать переменной `TG_PANEL_DATA`.

**Перенести аккаунты с сервера** в программу: закройте программу, скопируйте в её папку данных файлы
`panel.db` и `secret.key` из `data/` сервера и запустите снова. Не держите одни и те же сессии
одновременно и на сервере, и в программе — Telegram может сбросить сеанс.

## Первый запуск без подписи

Сборки не подписаны сертификатом разработчика, поэтому система переспросит:

- **Windows**: «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».
- **macOS**: при первом открытии — правый клик по программе → «Открыть» → «Открыть». Если macOS пишет,
  что программа «повреждена», снимите карантин: `xattr -cr "/Applications/TG Panel.app"`.
- **Linux**: для AppImage на некоторых дистрибутивах нужен `libfuse2`
  (`sudo apt install libfuse2`), или используйте архив `tar.gz`.

## Сборка

Собирать нужно на той системе, под которую нужна программа (PyInstaller не собирает «крест-накрест»).
Под все три системы сразу программу собирает GitHub Actions — `.github/workflows/desktop.yml`: на каждую
правку в `desktop/`, `app/`, `static/`, `requirements.txt` (файлы — в артефактах запуска), а при новой версии
в `main` или теге `v*` — ещё и релиз. Можно запустить и вручную: Actions → «Десктоп-приложение» → Run workflow.

Локально — Python **3.12**:

```bash
# Linux / macOS
python3.12 -m venv desktop/.venv
desktop/.venv/bin/pip install -r desktop/requirements.txt
desktop/.venv/bin/python desktop/build.py
```

```bat
:: Windows
py -3.12 -m venv desktop\.venv
desktop\.venv\Scripts\pip install -r desktop\requirements.txt
desktop\.venv\Scripts\python desktop\build.py
```

Результат — в `desktop/release/`. Установщик Windows собирается, если установлен
[Inno Setup 6](https://jrsoftware.org/isdl.php); AppImage — если есть `appimagetool` (или путь к нему
в переменной `APPIMAGETOOL`). Без них получаются только архивы.

Запуск из исходников без сборки: `desktop/.venv/bin/python desktop/launcher.py`
(флаг `--hidden` — сразу в трей).

## Как устроено

```
launcher.py ── окружение для app.config (DATA_DIR, WEB_HOST=127.0.0.1, случайный WEB_PASSWORD)
   │             в режиме «на моём сервере» свой сервер не запускается — окно открывает адрес панели
   │
   ├─ server.py ── поток: uvicorn + app.main (тот же FastAPI, что на сервере), свободный порт 127.0.0.1
   └─ shell.py ─── окно Qt WebEngine (Chromium) с интерфейсом static/; cookie входа кладётся в профиль
                   браузера напрямую; трей, уведомления, загрузки, внешние ссылки
```

| Файл | Что делает |
|---|---|
| `launcher.py` | точка входа: журнал, переменные окружения, одна копия, запуск сервера и окна |
| `server.py` | сервер панели в фоновом потоке, выбор порта (прошлый, если свободен — чтобы не терять localStorage) |
| `shell.py` | окно, трей, уведомления, загрузки, разрешения мини-приложений, внешние ссылки |
| `single.py` | одна запущенная копия (QLocalServer) |
| `autostart.py` | запуск при входе в систему для Windows, Linux, macOS |
| `connection.py` | выбор режима: на этом компьютере или на своём сервере, проверка адреса |
| `updater.py` | обновление из GitHub Releases: проверка, загрузка, установка после выхода |
| `paths.py` | папка данных по ОС, файлы сборки |
| `tg-panel.spec` | PyInstaller |
| `build.py` | значки, PyInstaller, упаковка под текущую ОС |
| `packaging/` | ярлык и установка для Linux, AppImage, установщик Inno Setup |

Встроенный браузер — Qt WebEngine из PyQt5: PyQt5 уже нужен opentele для чтения tdata, поэтому
отдельный движок (Electron и т.п.) не тянем. Код панели (`app/`, `static/`) программа не меняет: всё
отличие — в небольшом скрипте, который `shell.py` встраивает в страницу (скрыть «Выйти из панели»
и считать окно без фокуса «скрытым» для уведомлений).
