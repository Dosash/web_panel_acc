# Разработка

## Запуск

```bash
./run.sh
```

- Python-код (`app/`) — после правок **перезапустите сервер** (uvicorn запущен без `--reload`,
  чтобы не рвать соединения аккаунтов на каждом сохранении).
- Интерфейс (`static/`) — достаточно обновить страницу (F5).
- Для разработки с автоперезапуском: `.venv/bin/uvicorn app.main:app --reload --port 8080`
  (аккаунты будут переподключаться при каждом сохранении).

Зависимости зафиксированы в `requirements.txt`. Python именно **3.12**: opentele тянет PyQt5,
который на 3.13+ ставится ненадёжно.

## Структура

```
app/
  config.py        настройки из .env, ключи в data/
  storage.py       SQLite + шифрование сессий
  tdata_import.py  tdata → StringSession (opentele)
  manager.py       клиенты Telethon, события, сериализация
  lan_proxy.py     прокси веб-панели из локальной сети (отдельный порт)
  main.py          FastAPI: REST, WebSocket, статика
static/
  index.html       каркас страницы
  app.css          дизайн-система и компоненты
  app.js           состояние, рендер, API-клиент, модальные окна
docs/              документация
data/              база, ключи, кэш (в .gitignore)
```

## Соглашения

- Весь текст интерфейса и сообщений об ошибках — **на русском**.
- Комментарии в коде — на русском, только там, где неочевидно «почему».
- Фронтенд без сборки и без зависимостей: никаких npm-пакетов, только то, что работает в браузере.
- Новые эндпоинты — в `app/main.py` с `dependencies=A` (проверка входа). Ошибки Telegram не ловить
  вручную — их превращает в `400` общий обработчик `RPCError`.
- Сериализацию объектов Telethon — в `manager.py` (`message_dict`, `dialog_dict`), а не в эндпоинтах.
- Тяжёлые загрузки из Telegram оборачивать в `manager.media_slot(aid)`.

### Как добавить функцию (пример: «переслать сообщение»)
1. Эндпоинт в `main.py` (уже есть `/forward`).
2. В `app.js`: кнопка в `messageEl` → обработчик в `msgAction` → `api(...)`.
3. Иконка — добавить путь в словарь `ICONS`, если подходящей нет.
4. Описать в `docs/API.md` и `CHANGELOG.md`.

## Дизайн-система (`static/app.css`)

Цвета и радиусы — CSS-переменные в `:root` (тёмная тема) и `:root[data-theme="light"]`.
Никаких «голых» цветов в компонентах — только токены.

| Токен | Назначение |
|---|---|
| `--bg` | Фон приложения и рейки |
| `--surface`, `--surface-2`, `--surface-3` | Панели → поля/hover → активные элементы |
| `--elev` | Модальные окна, тосты, всплывающие меню |
| `--border`, `--border-strong` | Обводки |
| `--text`, `--muted`, `--faint` | Текст: основной → вторичный → третичный |
| `--accent`, `--accent-2`, `--grad`, `--accent-soft` | Акцент: синий → голубой, градиент, мягкий фон |
| `--danger`, `--ok`, `--warn` | Статусы |
| `--r-lg`, `--r-md`, `--r-sm` | Радиусы |

Компоненты: `.btn` (`.primary`, `.danger`, `.block`), `.icon-btn` (`.sm`), `.badge`, `.chip` (цвет
через `--c`), `.avatar` (`.xs/.sm/.lg`), `.segmented`, `.tile`, `.menu-list`, `.form`, `.drop`,
`.toast`, `.skel` (скелетон-загрузка).

Иконки: `icon("name")` в JS или `<span data-icon="name"></span>` в HTML. Стиль — линейные 24×24,
`stroke-width: 2`, скруглённые концы.

Адаптив: при ширине ≤ 860px чат открывается поверх списка на весь экран, кнопка «назад» видна.

## Подводные камни

- **opentele бросает `BaseException`**, а не `Exception`. В `tdata_import.py` ловим `BaseException`
  и пропускаем только системные (`_reraise_fatal`).
- **Кэш сущностей.** `StringSession` не хранит access_hash между перезапусками. `manager.entity()`
  при промахе грузит все диалоги один раз. Новые методы, работающие с чатом по id, должны брать
  собеседника через `manager.entity(aid, cid)`.
- **Высота ленты.** У `.app` стоит `grid-template-rows: minmax(0, 1fr)` и `min-height: 0` у колонок —
  без этого лента сообщений растягивает страницу на всю длину канала.
- **Ленивые картинки.** `loading="lazy"` не работает у картинок, которых нет в DOM; аватары грузятся
  через `IntersectionObserver`.
- **Большие числа.** `hash` сеансов — int64, передаётся строкой (в JS теряется точность).
- **Flood wait.** Массовые запросы к Telegram (аватары, медиа, диалоги со всех аккаунтов) могут
  вызвать ограничение. Telethon сам ждёт до 30 секунд (`flood_sleep_threshold`), дольше — ошибка 400.

- **Веб-панель из локальной сети** открывается в iframe через прокси на отдельном порту, а не по пути
  `/lan/...`: в JS её под-панелей зашиты абсолютные пути (`/api/...`, `/parser/assets/...`), и `/api`
  пересекается с API TG Panel. Вторая копия панели для проверки должна брать другой порт прокси:
  `LAN_PANEL_PROXY_PORT=8091 .venv/bin/uvicorn app.main:app --port 8090`.

## Отладка

- Логи сервера — в терминале `./run.sh`.
- Проверить API без интерфейса: `curl http://127.0.0.1:8080/api/accounts`.
- События WebSocket видны во вкладке Network → WS в DevTools браузера.
- Если аккаунт в статусе `error` с «Сессия недействительна» — сеанс завершён в Telegram;
  загрузите tdata заново (сессия обновится в том же аккаунте).
